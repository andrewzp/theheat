# Airport observations and publication memory

A same-time temperature comparison describes two named airport observations.
Sharing an airport, a date or a display name does not establish one continuing
physical weather event, and a later comparison does not establish its duration.

Unbound airport comparisons therefore supply no physical ongoing-event or
same-event history. Their publication text, source event IDs, general history,
category cooldown, novelty and framing remain available. Existing stored rows
remain intact. Source pair/day deduplication and all source and publication checks
are unchanged.

Full or compact restored publication metadata keeps the existing airport-family
restriction, including older records identified by their source marker. That
marker is not source evidence: it cannot qualify a fresh claim or grant review
or posting approval. Explicit physical bindings still require the existing
resolved context and validations; they cannot fall back to observation memory.

Offline tests use invented CSV and catalog data through the real parser, source
runner, audit, queue, publication recorder and writer request. They check changed
airports, repeated pairs, later observations, input order and restored history.
They establish the memory boundary, not real weather, model quality or X delivery.
