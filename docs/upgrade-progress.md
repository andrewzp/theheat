# TheHeat upgrade acceptance ledger

As of 11 October 2026: **6 complete bounded repairs, 35 partial packages, 4 untouched planned deliverables** across the original 45-package upgrade. The full upgrade remains unfinished. Package sizes differ, so these counts are not a completion percentage.

The [product priorities](plans/2026-09-09-product-priorities.md) remain sharper writing, worldwide coverage, reliable sources, useful graphics, lower operating cost and fewer regressions. Code and infrastructure are means to those outcomes; test counts do not measure editorial quality, global recall or savings.

## How to read progress

**Implemented** means code or an evidence artifact exists. **Tested** names exercised cases and environments; invented fixtures do not establish source truth or model quality. **Merged** means the change reached main. **Deployed** means the relevant runtime or dashboard package was released; a Git push alone does not deploy the dashboard. **Runtime-observed** means a particular real execution was inspected. **Accepted** means the original package criteria are supported, including any required integration or measurement.

**Complete** below applies to the six original deterministic repair contracts, whose implementation, tests and release evidence are recorded. It does not certify every future route or the whole system. **Partial** credits delivered parts and retains the original remaining acceptance. **Untouched** means the planned deliverable has not started; existing modules and prerequisite fixes do not count as its implementation.

Gist remains the production authority. SQLite/PostgreSQL command, job and media components have substantial local and real-PostgreSQL test coverage, but are not a completed production migration. Automatic publishing remains paused. The [production-pause runbook](runbooks/production-pause.md), [PR621](https://github.com/andrewzp/theheat/pull/621) and [PR640](https://github.com/andrewzp/theheat/pull/640) distinguish configured pause, retained workflow history and real failures; a scheduled collector skip has been observed, but authenticated deployed dashboard pause behavior remains unobserved. Configured pause does not prove every worker stopped or all spending ceased.

The protected MODIS editor preview in [PR638](https://github.com/andrewzp/theheat/pull/638) is merged and manually deployed. Its local desktop/mobile/keyboard and stale-response checks passed; deployment and anonymous protection were verified. Signed-in production preview interaction remains unobserved. Read-only preview is separate from attachment, joint approval and platform delivery.

The local draft workbench in [PR642](https://github.com/andrewzp/theheat/pull/642) is merged and its dashboard code manually deployed. Actual local browser checks exercised authenticated loopback commands, PostgreSQL persistence and a separate consumer. The next checked-candidate admission path and qualified PM2.5 preview are implemented with local integration tests; their combined browser/release acceptance remains pending. An explicit staging TLS adapter does not establish hosted application recovery or production migration.

## Evidence limits and completion gates

The historical set retains three distinct classes: 31 receipt-backed posts, seven posted-state texts without IDs and 25 generation-memory texts with unverified publication. It is not the complete publication archive or a controlled engagement comparison. Preserve exact historical material privately; never import generation memory as confirmed publication. Missing primary packets, uncertain QC timing and unresolved source/product discrepancies stay explicit. Known bad posts are negative cases, not positive writing examples.

The original phase gates still apply: truthful operations and deterministic containment; one authenticated authority with reconciled import/restore/jobs/outbox; measured scientific supply and global-event coverage; a unified editorial engine and accepted review journeys; then reconciled economics, useful outcomes, interpretable experiments and safe retirement. A completed repair, large test suite or deployed preview does not replace those gates.

Next work should connect existing components into complete source-to-candidate-to-event and edit-to-check-to-review-to-delivery paths. Continue independent local work while access or human adjudication blocks a particular gate. Code release does not authorize paid experiments, production migration, publication or public corrections.
