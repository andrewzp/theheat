# TheHeat upgrade acceptance ledger

As of 21 October 2026: **7 complete packages, 37 partial packages, 1 untouched planned deliverable** across the original 45-package upgrade. The full upgrade remains unfinished. Package sizes differ, so these counts are not a completion percentage.

The [product priorities](plans/2026-09-09-product-priorities.md) remain sharper writing, worldwide coverage, reliable sources, useful graphics, lower operating cost and fewer regressions. Test counts measure exercised cases; they do not measure editorial quality, global recall or savings.

## How to read progress

**Implemented** means code or an evidence artifact exists. **Tested** names exercised cases and environments; invented fixtures do not establish source truth or model quality. **Merged** means the change reached main. **Deployed** means the relevant runtime or dashboard package was released; a Git push alone does not deploy the dashboard. **Runtime-observed** names a particular real execution. **Accepted** means the original criteria are supported, including required integration and measurement.

**Complete** applies to the six original deterministic repairs and the domain schema/architecture definition, with their recorded criteria, integration tests and release evidence. The domain definition does not establish hosted or production adoption. **Partial** credits delivered work while retaining the remaining original criteria. **Untouched** means the deliverable has not started; prerequisites do not count as its implementation.

Gist remains the production authority. Substantial local PostgreSQL command, job, editor, media, delivery and restore workflows are accepted in their named fixture scopes; they are not a production migration. Hosted identity, all-writer fencing, application restore and cutover remain open. Automatic collection, draft generation and publication remain paused. The [production-pause runbook](runbooks/production-pause.md) separates configured controls from runtime evidence. A named scheduled skip or disabled dashboard control does not establish every worker stopped or all spending ceased.

Signed-in read-only Dashboard, Sources, Health and feedback presentation have been observed. [PR691](https://github.com/andrewzp/theheat/pull/691) adds observed disabled collection controls and clear configuration-versus-history labels. A deployed UI or policy manifest is separate from accepted hosted mutations, media attachment and platform delivery.

Recent releases include the domain definition and bounded selected rejection context in [PR701](https://github.com/andrewzp/theheat/pull/701), qualified station-comparator preparation in [PR697](https://github.com/andrewzp/theheat/pull/697), warning message/event timing in [PR698](https://github.com/andrewzp/theheat/pull/698), and local manual event-portfolio planning in [PR699](https://github.com/andrewzp/theheat/pull/699). The lifecycle limits below still apply; none establishes independent model-writing quality, global recall or invoice savings.

## Evidence limits and completion gates

The historical set retains three distinct classes: 31 receipt-backed posts, seven posted-state texts without IDs and 25 generation-memory texts with unverified publication. It is not the complete publication archive or a controlled engagement comparison. Preserve exact historical material privately; never import generation memory as confirmed publication. Missing primary packets, uncertain QC timing and unresolved source/product discrepancies stay explicit. Known bad posts are negative cases, not positive writing examples.

The original phase gates still apply: truthful operations and deterministic containment; one authenticated authority with reconciled import/restore/jobs/outbox; measured scientific supply and global-event coverage; a unified editorial engine and accepted review journeys; then reconciled economics, useful outcomes, interpretable experiments and safe retirement. A completed repair, large test suite or deployed preview does not replace those gates.

Next work should connect existing components into complete source-to-candidate-to-event and edit-to-check-to-review-to-delivery paths. Continue independent local work while access or human adjudication blocks a particular gate. Code release does not authorize paid experiments, production migration, publication or public corrections.
