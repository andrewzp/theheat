# Shared sourced generation in local preview

The local source chooser requests one draft from an immutable, audited source brief. Ordinary inputs use the same writer request and one-sample batch engine as the explicit automatic starter. Eligible urgent inputs use the bounded synchronous writer path. Both require the existing four checks and checked-candidate admission. Admission creates a pending, unapproved draft. Editing still invalidates obsolete checks and approval.

This is an experimental local PostgreSQL workflow. It does not select a production backend, activate batch transport, collect sources or enable publishing. Gist remains the production store. Production producer trust, all-writer migration and billing reconciliation remain separate work.

The old free-text `/api/generate` provider call is removed. Outside an explicitly configured local preview, generation is unavailable. Production pause takes precedence. An authenticated local `GET /api/generate` lists at most 16 server-retained briefs; `POST` accepts only the durable `request_sourced_generation` command with `brief_id`, `brief_sha256`, `expected_state_version` and `expected_policy_sha256`. No browser-supplied prose, model, source payload or spending amount is accepted.

The preview adapter accepts an optional owner-only `--generation-inputs` JSON file with `current_inputs` and a trusted `reservation` (`estimate_sha256`, `reserve_micro_usd`). Inputs are retained beforehand through `PostgresCommandAuthority.retain_generation_input`. The file is reread for current authority; removing, superseding or expiring a brief blocks new work. This local allowlist is not proof of scientific truth or a production source-verification service.

The reservation digest must identify a complete immutable document retained through the local-only `retain_generation_reservation` method, never an HTTP upload. Its exact fields are `schema_version: 1`, `basis: "invented_local_allowance"`, `provider: "anthropic"`, `role: "writer"`, `model`, `policy_sha256`, `brief_ids`, `reserve_micro_usd`, `valid_from` and `valid_until`. It covers 1–16 unique brief hashes, one exact current writer model/policy and a positive bounded integer allowance during a strict UTC window. The full canonical document must match its digest, configured amount and current brief before registration, a request, a result read or interpretation. Missing, mismatched or expired documents refuse new work. Already granted response bytes and unknown charges remain retained after later allowance drift or expiry. This invented local allowance is not a provider quote, real settlement or production spending authorization.

`SourcedGenerationClient` gives an explicitly injected automatic caller the same command path. Both triage drains count queued work as a selected slot, not a saved draft or provider attempt. Source callbacks with deferred side effects are excluded. An unavailable explicit adapter cannot fall back to the legacy provider.

Separate explicit worker invocations call `execute_sourced_generation_once` with `submit`, `collect` or `capture`; execution is off unless explicitly enabled. Collection reuses a retained complete receipt by default. `refresh=True` is an explicit bounded read of existing provider work, never another submission. Source, role, memory, policy and reservation are revalidated before requests and interpretation. Returned bytes from an already granted attempt remain retained after later authority drift; that does not permit interpreting or promoting stale results. A lost acknowledgment keeps the hold and unknown outcome.

For an urgent retained input, the existing command enrolls the synchronous job. The explicit synchronous worker grants one SDK request only after checking the current source, operator/session, allowance and rejection cache. It retains the original request and response for the same check/admission pipeline; an uncertain dispatch is not automatically repeated. Passive response retention after later authority drift does not authorize another request or a saved draft.

The retained GHCN source path now joins source/history retention to one synchronous writer, four required checks and a saved pending draft in the local workflow. Writer, fact-check and critic requests use an exactly bound compact claim view; scientific eligibility and local factual checks still replay the full retained evidence. The source remains explicitly allowlisted, and first enrollment fixes its deadline. Retries cannot renew it. Baseline changes, original writer/checker authorization changes, expired check requests or altered receipts prevent admission. Older source/check formats refuse the new inputs rather than treating them as ordinary unchecked evidence.

Passive GHCN listings can report that checks were recorded without claiming current scientific validity. Adding the candidate to drafts freshly revalidates its source and all exact receipts. The local checker requires an explicit credential and synchronous HTTP-transport capability for this path; malformed options never select a default network transport. Offline acceptance uses invented credentials and SDK transports. Real-provider credential provisioning, hosted operation, temperature-media integration and measured costs remain unaccepted.

The writer's existing lease may briefly delay the checker. `checks_available_at` is only a current availability hint. The UI waits and rereads it; the backend independently acquires checker ownership and rejects an early or stale request. Refreshing the dashboard makes no provider request.

Each source row may include `writer_usage`: exact `job_id`, `custom_id`, `receipt_id` and `intent_id`; current `reservation_state`; existing `usage_status` semantics; nullable numeric `counts` using the existing Anthropic token field names; `cost_usd: null`; and `cost_status: "unreconciled"`. Before a job exists it is null. One chosen receipt is projected once, without summing duplicate reads. Tokens are observations, not a bill. This lane neither prices nor settles charges or releases dispatched holds.

Offline acceptance uses invented source inputs through the existing fire intern, the actual Anthropic SDK with explicit HTTP fixtures, separate checker processes, actual local PostgreSQL and actual dashboard route/component code. The tests cover manual/automatic deduplication, spending refusal, role/source/policy drift during HTTP, expired leases, crash recovery and restore to a fresh owned cluster. Browser interaction, hosted qualification and production operation are distinct acceptance gates.
