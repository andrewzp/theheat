# P32: bounded news verification

A three-page download limit did not bound the number of paid verification requests: many impacts citing one page could each trigger a model call. The news lane now permits at most six verifier invocations per retrieval. It visits one impact per story before returning for additional impacts, preserving original story/impact order in the retained output. This improves allocation of this limited work; it is not a measured global recall or editorial-quality result.

Every retained grounded impact still requires an explicit supported verdict. An unchecked sibling cannot inherit approval. The cache lasts only for the current retrieval and matches the full impact packet, event place/window and fetched page text. Changed claims, values, citations, dates, places or reporting windows require another check. Only completed boolean verdicts are cached; provider failures and malformed output are not. There is no cache reuse across retrievals or model/prompt deployments.

Cited page text and failed URLs are shared within the retrieval. At most three distinct page-fetch invocations occur; the existing HTTP helper may retry those reads. Once the model allowance is exhausted, a new page is not fetched just to discard its claims. Exact cached verdicts remain usable without another model request. The structured NIFC leg is unaffected.

Both news SDK sites explicitly configure one attempt, including the original request. Thus the normal lane has one grounded-search model request and up to six separate verification model requests, with no application retry around these sites. Provider-side search fanout, token quantities, billing and charges from other roles remain outside this limit. The setting is not a monthly/account dollar ceiling; the partial-cost reader continues to say so. The installed SDK currently defaults to one attempt when retry options are absent; this change makes that posture explicit rather than claiming an observed retry reduction.

Returned usage diagnostics separate model requests, exact cache hits, model/page budget skips, page failures and model errors. Budget exhaustion or unavailable verification makes the source run degraded, including when some NIFC or verified events survive. Unsupported claims alone are a legitimate result. Intentional budget-only degradation has its own class: the sentinel neither opens a repair incident nor closes an earlier outage on that basis. A real verification/leg failure still follows the failure path. These diagnostics are retained in source-run details and notes; no dashboard layout change is included.

Validation covers a thousand-claim page (six checks, 994 withheld), one-first-claim-per-story ordering, exact reuse and changed provenance, independent page/model limits, failed-request consumption, malformed/negative verdicts, source health and actual incident planning. An actual Google SDK client with a mocked HTTP transport verifies that a transient503 makes one HTTP request at each news model site. Tests make no live model calls.

Automatic publication stays paused.

Remaining work includes account-wide enforcement, complete role/platform/hosting attribution, durable reservations and late-result persistence, bounded output/retry policies across every model route, independently qualified global reference events, sharper copy evaluation and production media approval. Historical63-text evidence classes and factual findings are unchanged.
