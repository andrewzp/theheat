# P09a: inspect the full rainfall grid watchlist without enlarging remote fallback

The previous grid path downloaded one complete daily IMERG file and then inspected only the first 75 configured cities. A qualifying signal later in the watchlist could never reach the detector. Local extraction now covers the entire supplied watchlist after validating geography/identity and removing exact duplicate sampling identities. Reordering the list no longer changes the set of grid readings. This is structural watchlist eligibility, not independent scientific qualification of the grid.

`max_cities` now controls only per-city remote paths. OPeNDAP and the separate model witness each retain a hard ceiling of 75 cities, and a smaller requested limit is honored. `None` or a larger configured limit no longer removes the remote ceiling. Grid extraction remains full-watchlist even when this network limit is smaller or zero; the existing orchestrator still rejects configured values below one. This intentional behavior prevents increased local coverage from causing a larger remote fan-out during a grid outage. It is a city bound, not an all-in request/token/dollar ceiling: existing date probes, retries and witness model calls remain separate bounded mechanisms. The default fallback still samples a prefix, so full fallback geographic fairness remains P19 work.

Invalid/missing names and absent/nonfinite/out-of-range explicit coordinates are skipped before identity deduplication and indexing, so one bad row cannot abort the complete grid or be clamped to a pole. Duplicate canonical sampling identities produce one reading. Nonfinite or negative precipitation cells are missing evidence and are omitted; they are no longer converted into a zero-rain observation. A file containing multiple daily slices is rejected instead of silently using the first. The existing single-daily-grid dimension and indexing/product assumptions are otherwise unchanged.
