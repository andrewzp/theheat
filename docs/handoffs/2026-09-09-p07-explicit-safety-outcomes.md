# P07: completed safety checks and bounded exact reuse

The safety stage previously returned a pass when its credential was absent, the provider failed, or the answer was empty or unexpected. It now exposes a completed, failed or unavailable execution separately from the allow/reject verdict. Only a completed, unambiguous YES or NO establishes a verdict. The existing tuple interface maps everything else to a blocking result with an explicit reason, so drafting and both reviewed posting paths inherit the behavior. This is a content-safety decision, not factual certification.

Completed results can be reused for five minutes in the same Python process. The cache holds at most 128 entries, matches exact text, rendered prompt and model, retains the original completion time, and records no additional model response on a hit. Missing credentials still block a previously cached pass. Changed text, model, prompt, expiry or reversed monotonic time requires a new check; failed and ambiguous results never enter the cache. Deterministic rules run on every pipeline invocation. Concurrent in-flight calls are not coalesced, and results do not persist across workflow processes. This is bounded repeat-call avoidance, not measured invoice savings or an account-wide spending ceiling.

The original content-safety prompt is unchanged in meaning and bytes after interpolation. It now participates in the runtime editorial policy identity alongside writer, critic and fact-check prompts. Existing current-policy approval checks therefore reject reviews from the old policy. The generated dashboard policy manifest must be manually deployed with this release; review eligibility still requires a fresh matching bot inventory. A malformed prompt without the tweet placeholder cannot establish a pass.

The SDK client explicitly sets a 90-second timeout and one attempt, including the original request. The installed SDK already defaults to one attempt when retry settings are absent, so this pins the posture rather than demonstrating a retry reduction. Returned usage is captured before response parsing. An accounting observer failure cannot alter a completed verdict or cause another model request. Provider exception bodies are not retained in the failure reason. Google pricing and complete spending enforcement remain separate work.

Validation uses synthetic fixtures and mocked transport, including a real Google SDK client receiving a transient HTTP 503 exactly once. Regressions cover completed positive/negative decisions, invalid output, unavailable credentials, provider failures, accounting failure, exact reuse and invalidation, expiry, cache bounds, and deterministic rules after a cached pass. Real manual and due-draft orchestration paths with mocked external senders verify that unavailable checks revoke approval, retain a pending draft, and create no publication receipt. Existing tone-only examples now explicitly mock the required check and do not claim that the weather statements are true.

The full P07 plan remains incomplete: durable typed executions, cost-aware routing across every model role, evidence caching, independent editorial evaluation and comprehensive check-status UI are still open. Historical evidence stays at 63 retained texts: 31 receipt-backed, seven posted-state without IDs and 25 generation-memory texts with unverified publication. Selected live observations are not a complete account archive or proof of editorial lift. Known threshold/record and forecast/observation errors, the Bavi position evidence, and the unresolved Congo, Barrow and Beaver Dams qualifications remain the baseline. No paid evaluation, test tweet, automatic publishing activation or public correction is part of this release.
