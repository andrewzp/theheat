# P07: offline scheduled-canary fixture repair

The three scheduled voice-canary fixtures were checked against the P05 contract on source-supply base `190deee`. Before this patch, `verkhoyansk_monthly_high_bundle` and `marine_heatwave_bundle` failed `missing_provenance` before the writer provider call. `co2_milestone_bundle` passed. A canary requiring two producers out of three therefore could not pass with these packets, even if billing and transport worked. This is a separate latent fixture failure; it does not explain or supersede the parent-reported insufficient-credit failure in run `34359176142` at `10832af`.

## Changes

All three packets now identify themselves as synthetic test data, with explicit fixture source/product identity. These source labels establish test provenance only; no agency data was retrieved or certified. The temperature case retains its provider-local date/window and forecast wording but drops an unqualified bare archive-record comparison. The CO2 case specifies a station daily mean and threshold, without a global-mean claim or unsupported historical growth figures. The ocean case retains the 60°S–60°N mean snapshot and explicitly withholds record, streak, anomaly-baseline and marine-heatwave classification claims. Legacy fixture names remain compatible with the weekly replay list.

The scheduled test preflights all three bundles before making any provider call. Broken packets now produce an actionable fixture-contract failure instead of being counted as ordinary writer kills and reported as a degraded provider lane. The writer and safety checks remain unchanged. No scheduled test body was executed during this work, and no workflow, paid cadence, threshold or retry policy was changed.

The existing acceptance checks already permit a short complete single sentence: there is no minimum character count or mandatory second sentence. Offline regressions exercise each fixture through the actual writer parsing/length logic and canary sampling helper using one local provider response and a mocked safety-LLM boundary. Real deterministic safety checks still run, and a banned opener remains rejected. These examples demonstrate acceptance of the compact style; they do not certify grammatical completeness or factual accuracy for arbitrary model output.

The cost documentation now states the actual invocation bound: three initial writer invocations plus at most three re-samples. Writer parse/length/provider retries and the existing safety call can increase the underlying request count. Earlier dollar estimates and the incorrect maximum of two re-samples were removed. No new call or evaluation stage was added.

## Validation and limits

**159 focused offline tests passed**, including seven new canary boundary cases plus the existing writer, evidence-contract and safety suites. Ruff and diff whitespace checks pass. Collection of the canary/replay directory with the new offline tests selects seven and deselects all 41 paid tests. A reference audit found no existing offline assertion depending on the removed fixture history: the weekly writer replay uses these three through its generic safe-or-kill and fabricated-phrase checks, while separate adapter tests construct their own events. Root reviewed the bounded diff and cleared it. Neither provider credentials nor live state were inspected and no network/provider calls were made.

The narrower packets may be less attractive to a live model than the old unsupported record/streak stories. This patch proves that all three are structurally prompt-ready and can reach the writer; it does not prove a live two-of-three producer rate, a billing recovery, a model-quality improvement or dollar savings. The canary still tests writer availability and basic safety rather than the full fact-check/critic/scientific publication pipeline. The source qualification and actual-tweet audit evidence limits remain in force. Root should keep a future naturally scheduled canary result distinct from this offline repair; no extra paid run is requested here.
